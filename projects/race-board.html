The Race Board

A live leaderboard for the Black Ops 7 race to Master Prestige that reads each streamer's rank straight off their Twitch broadcast, so nobody has to type in a score.

Year
2025
Made with
Python, Flask, streamlink, OpenCV, Tesseract, EasyOCR, Firebase
Links
Live siteSource on GitHubFrontend source
Why

A handful of streamers were racing to Master Prestige in Black Ops 7, and the only way to know who was ahead was to check in on every stream. I wanted the standings without the tab-hopping, so I built something to watch them for me.

It was just for fun. Nobody asked for it, which is most of the appeal.

How it works

Each channel gets its own capture thread. streamlink turns the channel into an HLS URL, OpenCV reads it, and a two-slot queue keeps only the newest frame, so a slow detector never builds a backlog. Every two seconds the detector looks at whatever is current.

Twitch stream→Newest frame→Find "PROGRESSION"→OCR level + prestige→JSON in Firebase→Static site

Is this the Progression screen?

Almost every frame is gameplay. The detector crops the top-middle of the frame, binarizes it three ways, and asks Tesseract for the word PROGRESSION. No word, no detection. When the header is found it becomes the anchor, and the level and prestige boxes are defined as percentages of it.

Reading the numbers

The level crop gets three binarizations, a 4x upscale and a digits-only Tesseract pass. Only plausible numbers get a vote, and the most common answer wins.

Prestige is stylized text, which is harder. EasyOCR goes first, Tesseract tries sixteen preprocessing and page-mode combinations if that comes up empty, and a fuzzy matcher forgives the usual misreadings: PRESTICE, PREST0E, PREST6E. "Prestige Master" is stored as prestige 20 so it sorts above everything else.

No server for the public site

The backend is the only writer, so state is a plain streams_data.json, re-uploaded to Firebase Storage on every save. theraceboard.com is one static page on GitHub Pages that fetches the file and ranks streamers client-side, prestige then level. Each row has an info button with the last annotated frame and the raw OCR text, so anyone can check the robot's work.

What it taught me
  1. 1

    Find the word, not the picture

    OCRing the header beat template-matching the UI; the old matcher is still in the repo, unused.

  2. 2

    OCR is a vote, not a read

    No single preprocessing pass gets trusted on its own.

  3. 3

    Teach the code your OCR's typos

    Part of the detector exists only to forgive a misread G.

  4. 4

    One writer, one JSON file

    With a single writer, a file in a bucket is a perfectly good database.

  5. 5

    Better OCR costs gigabytes

    EasyOCR reads the prestige font better and needs 1–2 GB of RAM to do it, hence the off switch.

Rough edges
  • Detection regions are fixed percentages, so a stream overlay sitting on the menu can push the text out of the box.
  • The code can tell when a reading goes backwards but doesn't reject it yet, so one bad read can drop someone down the board until the next good one.
  • It can't see you level up mid-match. It finds out when you open the Progression screen on stream.
