Claudio

A chatbot that plays Claudio: second-generation Italian-American, late 40s, runs the family restaurant in Brooklyn, and has opinions about your chicken parm.

Year
2025
Made with
HTML, CSS, vanilla JS, one Firebase Function, Claude Sonnet 4.5 with web search
Links
Live siteSource on GitHub
Why

This was my first time playing with prompt building. I'm Italian-American, wrapping a language model in that heritage sounded like fun, and Claude → Claudio was too on the nose not to do.

How it works

The page is plain HTML and one ES module, no build step. It keeps the conversation in a browser array and sends the whole thing to a single Firebase Function every turn. Nothing is stored, so a refresh wipes Claudio's memory of you.

The function makes one call to Claude Sonnet 4.5 with a long system prompt: grandparents who came from Sicily in the 1930s, a Brooklyn childhood, Italian that's mostly about family, food and feelings, and an explicit instruction to skip the caricature. Then it asks him to work in two steps.

Your message→<character_analysis>→<response>→Chat bubble

Hiding the backstage

Claudio thinks first, inside <character_analysis> tags: which expressions fit, how a restaurant owner would see it, which family story applies. Then he answers inside <response>. The client shows only the answer.

If the closing tag gets cut off by the 1024-token limit, the client falls back to everything after the opening tag. If there's no tag at all, you get an apology and a Retry button instead of a blank bubble.

Web search changes the shape

Claudio can look things up, like where to get chicken parm in Delco. With search on, the reply arrives as a dozen text blocks split around citations, so reading the first block got me his private thoughts and none of what he actually said. The function now joins every text block before the client parses anything.

Search is also paid for in input tokens. One chicken-parm question ran two searches and about 49k tokens, so it's capped at one search per turn.

Screens

The whole interface is a portrait, a text box and a send button. Claudio brings the rest.

What it taught me
  1. 1

    Server tools change the response shape

    With web search on, content[0] was Claudio's private thoughts, not his answer.

  2. 2

    Search is billed in input tokens

    One chicken-parm question cost about 49k tokens, so max_uses is now 1.

  3. 3

    Hidden reasoning is billed twice

    The UI hides the analysis but the history keeps it, so every turn re-pays for the earlier thinking.

  4. 4

    Tag-based output needs a way out

    A fallback regex and a Retry button beat an empty chat bubble.
